# 阶段边界（Phase boundaries）

**阶段（phase）** 是会话内的一块工作——逼问、实现、QA。它的定义是*故意*模糊的：当你想"行，这块做完了"的时候，一个阶段就结束了。

**阶段边界**是两个阶段之间的空隙，而这里**是**这个决策唯一该出现的地方。阶段中途没什么可决策的——要么继续，要么把剩下的工作拆给子 agent。阶段中途压缩上下文会让 agent 丢掉线索。

## 五个选项

| 选项 | 它做什么 |
| --- | --- |
| **继续（Continue）** | 留在当前会话。完全不切换上下文。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写一个可携带的 markdown 文件，用它给任意位置的会话打底。 |
| **子 agent（Subagent）** | 把任务送到它自己的上下文窗口，拿一份报告回来。 |
| **`/compact`** | 压缩当前上下文，用摘要给新会话打底。 |

## 决策树

在边界处**自上而下**走。**第一个"是"就赢**。

**1. 你能在这个会话里继续吗？** 有两件事会让答案变成"是"：下一阶段把当前阶段当作**一手来源**；或者你剩下的**智能区**（约 150k token）足够装下下一阶段。逼问 → 实现是标准的"是"：实现想要的是原样的推理，不是推理的摘要。继续不花成本也不丢东西，所以**先把它排除掉**，再考虑别的。

**2. 当前上下文与接下来要做的事无关吗？** 这个会话里的一切——探索、决策、死胡同——都可丢弃吗？如果是，**`/clear`**。它是棋盘上最便宜的一步：不花时间，还回整个窗口。`/clear` 也不是终结——旧会话仍然可以恢复。

**这件事做错的代价是单向的**。clear 掉一个*相关*的上下文，你就丢掉了所建之物背后的 **why**，而且再怎么回读 diff 也要不回来。

**3. 你需要交接吗？** `/handoff` 范围很窄。只有当你处于以下情况时才需要：

- 换到**新平台**（Claude → Codex）；
- 搬到**新目录**或新仓库；
- 把工作交给**同事**；
- 或者在第 3 步**阶段中途**发现一个支线任务，想分叉出去又不打断手上的事。

这个清单就是全部适用条件。`/handoff` 买到的是**可携带性**——一个能旅行的文件。如果没有任何东西要旅行，你就不需要它。

**4. 这个任务能离线（AFK）做吗？** 它收得够紧吗——你离开键盘、不盯着也能跑？那就把它送给**子 agent**，当前会话原封不动。自动化审查是标准案例：agent 读 diff 出报告，它做的时候不需要你在场。

**5. 否则，`/compact`。** 上下文相关、同一平台、同一目录，而且你需要留在回路里——这是决策树的落点，而且**经常**落在这里。给它一句指令（`/compact 我们接下来要 QA 这块区域`），让摘要保住下一阶段需要的东西。

`/compact` 是**默认值，不是第一个伸手去够的选项**。它在树的底部，因为它上面那四个问题要么更便宜、要么更精确。人们一上来就用它时的失败模式是：新会话对某个被摘要抹平的决策**自信地判断错误**。

## 一手来源与二手来源

除了**继续**以外的每一个动作，都会把一个**一手来源**变成**二手来源**——真实发生过的会话，被它的摘要替代。这笔交易的形状永远一样：

| 来源 | 信息量 | 噪音 | 可腾挪空间 |
| --- | --- | --- | --- |
| 一手（继续） | 完整 | 多 | 少 |
| 二手（`/compact`、`/handoff`） | 有损 | 少 | 多 |

这就是为什么问题 1 排在最前面。只有"留下的成本大于它省下的"时，你才付这份有损的代价。

## 这些都是判断题

这些问题不是客观题——每一个里面都有口味成分，同一个边界在不同日子可能得出两种答案。它的价值在于**按顺序**问、在**边界处**问，而不是在干活干到一半时问。
