你在设计**收钱的机制**。这决定的不只是收入，还包括：**你要建什么系统、要守什么承诺、要扛什么成本**。

> **本技能的产出必须由人拍板。** 你提供方案、证据和算式，**不替用户决定价格**。

---

## 一、先算单位经济（不会算就别定价）

定价不是数字游戏，是**算术题**。必须算出这四个数：

```
【单价 ARPU】    一个客户一个月/一年给你多少钱
【变动成本 VC】  多服务一个客户，你多花多少
                 （服务器增量、API 调用、短信、支付手续费、人工支持）
【毛利 GM】      ARPU − VC        ← 必须是正数，且要好看到能覆盖固定成本
【回本周期】     获客成本 CAC ÷ 月毛利   ← 决定你能不能"花钱买增长"
```

**固定成本**（服务器基础费用、域名、你的时间）**不摊进 VC**——它是"卖够多少个才回本"的问题：

```
盈亏平衡客户数 = 固定成本 ÷ 单位毛利
```

**一个人做项目的特殊项：你自己的时间要不要算成本？**
- **算**（推荐）：按你能接受的时薪估。否则你会做出"看起来很赚，实际上是给自己发了份低薪"的生意。
- 支持成本是**最容易被低估**的一项。真实用户的提问量通常是最乐观估计的 3 倍。

**红线**：`GM < 0` 时，**卖得越多亏得越多**。这时候提价或砍成本，不要用"规模效应"骗自己。

## 二、选收费方式（决定系统复杂度）

| 方式 | 适合 | 系统要建什么 | 坑 |
|---|---|---|---|
| **一次性买断** | 工具类、交付明确 | 只要支付 + 授权码/下载 | 没有续费收入，每年要重新卖一遍 |
| **订阅（月/年）** | 持续提供价值、有服务成本 | 订阅状态机 + 续费 + 宽限期 + 升降级 | **状态机最容易写错**，宽限期和降级必须处理 |
| **按量计费** | 成本随用量明显变化（AI 调用、存储、短信） | 用量计量 + 额度 + 扣减 + 对账 | **必须和成本挂钩**，否则被薅死 |
| **额度包/预付** | 现金流优先，客户怕订阅 | 余额 + 扣减 + 过期策略 | 过期条款要合法合规，别做隐性吞余额 |
| **免费增值** | 获客成本高、产品可自传播 | 权限分级 + 升级引导 | 免费层成本必须**接近零**，否则免费用户拖死你 |
| **席位制** | 卖给团队 | 组织/成员模型 + 席位计数 | 席位计算规则要写清楚（停用的人算不算？） |
| **服务费/项目制** | 早期客户，需求不标准 | **几乎不用建系统** | 不可规模化——但**前 10 个客户这样最赚钱** |

**一个人做项目的务实顺序**：

```
项目制/手工服务（验证 + 现金流）
   → 一次性（产品化第一步）
   → 订阅（有持续价值后）
   → 按量/额度（成本随用量涨时才需要）
```

**别一上来就做订阅 + 按量 + 席位 + 免费层的混合模型。** 那是四套状态机，你会死在边界条件上。

## 三、定价的四个方法论（按顺序用）

### 1. 从价值定价，不从成本定价

**问："这个问题解决了他多少钱？"** 而不是"我花了多少服务器钱"。

```
如果这个问题每月让他损失 5000 元（人工/罚款/机会成本）
→ 定价 500~1500/月是合理的（10%~30% 的价值分成）
→ 定价 50/月是把钱留在桌上
```

**成本只能定下限，价值才能定上限。**

### 2. 三档锚定（最省事的定价结构）

```
基础档    ¥X      走量款 —— 门槛低、够用就行，用来降低"试试看"的成本
专业档    ¥2.5X   ★ 主力档 —— 你真正想卖的；标"最受欢迎"，把大多数人引到这里
旗舰档    ¥5X     锚点 —— 给少数人，顺便让专业档显得划算
```

> ⚠️ **一个常见的设计错误**：把基础档做成"80% 的人都会选它"。
> **那等于你没在卖主力档**——收入被自己锁死在最低价那一档。
> 若发现大多数人都选基础档，通常是**专业档给的价值不够明显**，而不是"用户就想买便宜的"。

**设计原则**：

| 档位 | 它该承担什么 | 自查 |
|---|---|---|
| 基础档 | **降低试用门槛**（不是为了赚钱） | 它是否够用但**明显有天花板**？ |
| 专业档 | **承担大部分毛利** | 目标人群里，多数人**应该**选它。选它的人够多吗？ |
| 旗舰档 | **当锚点 + 服务少数大客户** | 它是否让专业档显得划算？ |

**关键**：三档的差别必须是**能力/额度**，不是"功能开关堆砌"。
客户要能**一句话说清为什么升级**（说不清 = 档位设计失败，不是客户不聪明）。

**判断档位是否健康的快速方法**：看**收入构成**，不看**人数构成**。
健康的分布通常是少数人选高价档、但贡献可观收入；**不健康的是"人数和收入都压在基础档"**。

### 3. 价格锚定在竞品的"替代方案"上

对比对象**不是竞品**，而是**他现在的做法**：
- 继续用土办法（人工成本 × 时间）
- 雇一个人来做（人力成本）
- 用更贵的大厂方案（价格锚）

### 4. 提价纪律

- **早提价**比晚提价容易。有了 10 个满意的客户，比有了 100 个不满意的客户更好提价。
- **给老客户保留原价**（"早鸟价永久有效"）——成本很低，口碑很好，且能避免老客户流失。
- **一次提价幅度 ≤ 50%**，超过就换档位重新卖。
- **提价前先给新价值**，别裸提价。

**禁止**：靠打折获客。折扣会永久性地把你的价格锚拉低，而且引来最差的客户（只在乎价格的客户最不忠诚、最耗支持）。

## 四、免费与付费的边界

**免费层的目的只有一个：让人低成本地体验到"价值时刻"。**

| 免费给什么 | 付费锁什么 |
|---|---|
| 完整体验核心价值（限制次数/额度） | 更高额度 |
| 全部功能（限制数据量/时长） | 更多数据/更长历史 |
| 单人使用 | 协作/多席位 |
| 基础输出 | 高质量输出/导出/自动化 |

**免费层三条红线**：
1. **边际成本必须接近零**（否则免费用户会烧掉你的钱）。
2. **不能永久替代付费**（免费就够用 = 没人付费）。
3. **不能让免费用户消耗你的支持时间**（FAQ 和自助文档先行）。

## 五、必须提前想清楚的商业条款

这些条款会**直接变成系统需求**，所以定价阶段就要定：

- **试用期**：7 天还是 14 天？要不要信用卡？
- **续费失败**：宽限期几天？降级还是锁定？（**必须决定**，不能默认"不管"）
- **退款**：几天内无条件？按比例退？（**法令要求必须查**，尤其面向消费者）
- **取消**：随时可取消？当期结束还是立即生效？
- **涨价**：提前多久通知？
- **数据所有权**：客户走了，数据怎么导出、保留多久、什么时候删？
- **税务与发票**：要不要开发票？（国内面向企业几乎是必须）

> 这些是**人做的商业决策**。你负责把选项、常见做法和影响列清楚，等确认。

## 七、反模式清单

1. **成本加成定价。** → 从价值定价；成本只定下限。
2. **一上来做混合模型。** → 四套状态机，必死在边界条件。
3. **免费层成本不为零。** → 免费用户烧掉你的钱。
4. **靠打折获客。** → 拉低价格锚 + 引来最差客户。
5. **忘了做单位经济账。** → `GM < 0` 时越卖越亏。
6. **没决定续费失败怎么办。** → 系统里会长出未定义状态。
7. **低估支持成本。** → 按最乐观估计的 3 倍算。
8. **不给老客户保留原价。** → 提价时老客户流失，得不偿失。
9. **agent 替用户拍板价格。** → 只给方案和算式，人来定。
