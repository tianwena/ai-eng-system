# 加深（Deepening）

给定依赖关系，如何**安全地**加深一簇浅模块。假定你已掌握 [SKILL.md](SKILL.md) 里的词汇——**模块**、**接口**、**接缝**、**适配器**。

## 依赖类别

评估一个加深候选时，先给它的依赖分类。类别决定了加深后的模块如何跨接缝被测试。

### 1. 进程内（In-process）

纯计算、内存状态、无 I/O。**总能加深**——合并这些模块，直接透过新接口测试。不需要适配器。

### 2. 本地可替代（Local-substitutable）

有本地测试替身的依赖（Postgres 用 PGLite、内存文件系统）。有替身就能加深。加深后的模块在测试套件里带着替身运行来测试。接缝是内部的；模块的外部接口上没有端口。

### 3. 远程但自有（Ports & Adapters，端口与适配器）

你自己的、跨网络边界的服务（微服务、内部 API）。在接缝处定义一个**端口**（接口）。深模块拥有逻辑；传输作为**适配器**被注入。测试用内存适配器。生产用 HTTP/gRPC/队列适配器。

建议的措辞：*"在接缝处定义一个端口，为生产实现一个 HTTP 适配器、为测试实现一个内存适配器，这样即便跨网络部署，逻辑仍坐在一个深模块里。"*

### 4. 真正外部（Mock）

你不控制的第三方服务（Stripe、Twilio 等）。加深后的模块把外部依赖作为注入的端口接收；测试提供一个 mock 适配器。

## 接缝纪律

- **一个适配器意味着假想接缝，两个适配器意味着真接缝。** 除非至少有两个适配器成立（通常是生产 + 测试），否则不要引入端口。单适配器接缝只是绕路。
- **内部接缝 vs 外部接缝。** 一个深模块可以有内部接缝（对其实现私有、供它自己的测试使用），也有接口处的外部接缝。**不要因为测试会用到就把内部接缝暴露到接口上。**

## 测试策略：替换，不要叠加

- 一旦加深后模块接口处有了测试，旧的、针对浅模块的单元测试就变成了废料——**删掉它们**。
- 在加深后模块的接口处写新测试。**接口就是测试面。**
- 测试断言透过接口观察到的结果，而不是内部状态。
- 测试应该能在内部重构中存活——它们描述行为，不描述实现。如果实现变了测试就必须改，那它就是在**绕过接口**测试。
