# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它捕获用户学习这个主题的**原因**。每一个教学决策——接下来教什么、浮出哪些资源、设计哪些练习——都应当追溯回这份文档。

## 模板

```md
# Mission: {Topic}

## Why
{1-3 句。用户追逐的具体现实世界目标。掌握这项技能后，他的生活或工作会有什么变化？避免"为了理解 X"这类抽象表述——逼出底层的成果。}

## Success looks like
- {用户将能够做到的一件具体、可观察的事}
- {另一件具体的事}
- {……}

## Constraints
- {时间、预算、既有承诺、学习偏好，任何约束这个做法的东西}

## Out of scope
- {用户明确表示此刻不想去追的相邻主题——保护最近发展区}
```

## 规则

- **一个工作区一个使命。** 如果用户想学两件不相关的事，那是两个工作区。
- **具体胜于抽象。** "十月前跑完半马"胜过"变健康"。"给我的团队交付一个 Rust CLI"胜过"学 Rust"。
- **对含糊要顶回去。** 如果用户说不清为什么，先访谈他再动笔。**一个糟糕的使命比没有使命更糟。**
- **现实变了就修订。** 使命会变。用户目标移动时，更新这个文件——不要让一个过时的使命继续操纵未来的会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就不再是罗盘，而开始变成计划了。
