写给**任何 agent 会消费的文档**的参考——一个 skill、一份 `AGENTS.md` / `CLAUDE.md`、一份靠指针够到的文档。包装形式不同；**写法是一样的**：同一批杠杆让每一份都可预测——agent 每次跑**过程**相同，而不是产出相同。

当你写的文档是一个 skill 时，读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，里面讲 frontmatter、调用方式的选择和路由技能。

## 上下文指针（Context pointers）

**上下文指针**是**握在 agent 上下文里的**一个引用，它点出某份**在上下文之外**的材料，并编码了够到它的条件。一个 skill 的 description 就是一个；`AGENTS.md` 里点出某份文档的一行也是同一个对象。决定 agent 何时够到那份材料——以及够到得多可靠——的是指针的**措辞**，不是它的目标。一个**必须有**的目标挂在一个**措辞虚弱**的指针后面，就是一个**方差 bug**：先磨锋利措辞，只有磨不动时才把材料内联。

指针干两件事——陈述材料是什么，以及列出应该触发够它的那些**分支**（一个分支就是文档处理的一种不同情形，所以不同的运行会走不同路径）。**常驻加载的指针，每个词在每一轮都要付代价**，所以它比正文更该被狠狠修剪：

- **把领头的词放到最前面**——指针在那里执行它的触发工作。
- **一个分支一个触发器。** 给同一个分支改个名字的同义词，是同一个分支写了两次；合并它们，只留真正不同的分支。
- **砍掉正文已经承载的身份信息。**

## 两种负载

你添加的每份文档和每个指针，都在花掉两种预算之一：

- **上下文负载（Context load）** —— 常驻材料对 agent 窗口的成本：一行 `AGENTS.md`、一个 skill 描述、任何每一轮都坐在上下文里的东西，无论是否触发都在花 token 和注意力。
- **认知负载（Cognitive load）** —— 对人的成本：有哪些文档、什么时候该够哪一个。**人就是索引。** 它不是要被最小化的成本——它是人类能动性的价格；把它花在人的判断重要的地方，在不需要的地方移除它。

只通过指针够到的材料，**逃开了上下文负载**，代价是指针自己那一行；**完全没有指针**的材料，则完全由**认知负载**驮着。

## 信息层次（Information hierarchy）

一份文档由两种内容类型搭成——**步骤（steps）**（agent 执行的有序动作）和**参考（reference）**（按需查阅的定义、规则、事实）——它们自由混合：全步骤（一份菜谱）、全参考（一份审查的规则、这个 skill），或两者都有。核心决策是每一块在**信息层次**上的位置——一架按"agent 多急需这份材料"排序的梯子：

1. **文件内步骤** —— 主层级：agent 按顺序做什么。
2. **文件内参考** —— 按需查阅。常常是一个正当的**平级集合**（一份审查的每条规则在同一级台阶上）——这是好的安排，不是坏味道。
3. **披露出去的参考（Disclosed reference）** —— 推到单独文件里，通过一个上下文指针够到，只在指针触发时加载。范围从同文件夹的兄弟文件，一直到完全外部的、任何文档都能指向的参考。

**往下推得太少**，顶层就会膨胀；**推得太多**，你就把 agent 真正需要的材料藏起来了。这个张力就是全部决策。

**渐进式披露（Progressive disclosure）** 就是**沿梯子往下走**——移出主文件、藏到指针后面——让顶层保持可读。它主要不是 token 优化：**它是保护层次结构的方式**。分支是最好的披露检验：**每条分支都需要的就内联，只有部分分支才够到的就推到指针后面。** 当一份文档有步骤时，那些本该被披露出去的文件内参考会**埋住**步骤，让"去关注步骤"变成掷硬币——这是一个**方差杠杆**，不只是可读性杠杆。

**就近放置（Co-location）** 是文件内的配套动作：梯子决定一块内容**放多深**，就近放置决定到了那一层后**它旁边放什么**。把一个概念的定义、规则和注意事项放在**同一个标题**下，而不是散落各处，这样读到一部分就会把它的邻居一起带进来。检验标准：文档读起来应该像**为 agent 写的文档**——分组好的材料读起来就是那样；散落的材料不是。（与**重复**不同：重复是把**一个意思**在两个地方各写一遍；散落是把**一个意思**碎成很多片。）

**蔓延（Sprawl）** 是这里的失败模式：一份文档就是太长了，即便每一行都活着且独特。注意力在多余的篇幅上被摊薄，每一行额外的内容都是又一条需要保持相关的东西。解药就是梯子：把参考披露到指针后面，并按分支或序列拆分，让每条路径只携带它需要的。

## 步骤与完成标准

每个步骤都以一个**完成标准（completion criterion）**结束——告诉 agent"这事做完了"的条件。两个属性让它成为一个杠杆：

- **清晰度（Clarity）** —— agent 分得清做完没做完吗？一个模糊的边界（"达成理解"）会招来**过早完成（premature completion）**：在真正做完之前就结束这一步，注意力滑向"**看起来做完了**"。前方那些可见的步骤——**完成后步骤（post-completion steps）**——提供拉力；标准的清晰度是阻力。防守顺序：**先磨锋利边界**（局部、便宜）；只有当它本质上就是模糊的、**而且**你**观察到**了抢跑时，才通过拆分序列把后面的步骤藏起来——而隐藏只在**真正的上下文边界**上才有效（一次交接或一次子 agent 派发；内联调用会把后面的步骤留在上下文里，什么都没清掉）。
- **要求强度（Demand）** —— 它要求多少。"每一个被修改的模型都有交代"逼出彻底的工作，而"产出一份变更清单"不会。要求强度驱动**跑腿活（legwork）**——agent 在工作**之内**做的挖掘，它潜伏在措辞里，而不是被写成自己的一个步骤——而且它不绑定在单个步骤上："每条规则都应用"约束的是一整块平铺参考，正如"每个步骤都做完"约束的是一个序列，这就是为什么一份全参考文档依然能带上一条穷尽性门槛。

最强的标准**既可核查又穷尽**。

## 什么时候拆分

把一份文档拆成两份要花掉两种负载之一，所以**只有当这个切口挣得回来时才拆**：

- **按序列拆** —— 把一串步骤拆开：当"完成后步骤"会引诱 agent 抢跑眼前这一步时。把它们移出视野能在当前任务上逼出更多跑腿活。**当心反过来的情况**：合并序列会把每一步的后续步骤暴露给之后的动作，招来过早完成。
- **按调用方式拆** —— skill 特有的：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词（Leading words）

**引导词**是一个**已经活在模型预训练里**的紧凑概念，agent 在跑这份文档时用它思考（_lesson_（课）、_fog of war_（战争迷雾）、_tracer bullets_（曳光弹））。作为一个 token 反复出现、而从不作为一句话，它积累出一个分布式定义，并以最少的 token 锚定一大片行为区域，靠的是**召集模型已经持有的先验**。你自己造一个词也行，只要定义清楚，但**生造词召集不到先验**——你付出的是定义所需的 token，而一个预训练词是白给的；**先伸手去够已有的词**。

它**锚定两次**。在正文里锚定**执行**：只要这个词出现，agent 每次都够到同样的行为；而在平铺的参考里，它把注意力聚焦到"要去找哪一类东西"。在指针里锚定**调用**：当同一个词同时活在你的提示词、你的文档和你的代码库里，agent 会把那套共享语言和那份材料连起来，更可靠地够到它。

**主动去找用引导词重构的机会。** 一个三连词组在三个地方各拼一遍、一个指针花一整句话去指一个想法——每一处都是 begging to collapse（求着被压缩）成单个 token 的段落：

- "fast, deterministic, low-overhead" → _tight_（一个 _tight_ 的回路）。
- "a loop you believe in"（一个你相信的回路）→ _red_ —— 一个模糊的门变成二值的可观察状态（这个回路对 bug 变 _红_，或者不变）。

你**赢两次**：token 更少，而且给 agent 一个更锐利的钩子来挂它的思考。**假设每一份文档都携带着能被引导词退休掉的重述——去找出来。**

**否定（Negation）** 是这个杠杆旁边的失败模式：**用禁令来引导，会把被禁的行为拖进上下文，让它变得更可得，而不是更不可得**。_别想大象_，结果满脑子都是大象；否定是一个虚弱修饰词，会被那个被强烈激活的概念碾过去，于是禁令有一半读起来像是"去做那件事"的指令。**要正向提示**——陈述目标行为（"写一行的注释"），让被禁的那个从没被说出口。禁令只有在**你没法正向表述的硬护栏**时才挣得位置；即便如此，也配上正向目标，让注意力落在该做什么上。

## 修剪（Pruning）

- 每个意思保持在**单一事实来源**：一个权威位置，这样改变行为就是一处编辑。**重复（Duplication）**——同一个意思出现在不止一个地方——花掉维护成本和 token，并把一个意思在梯子上的显著度抬过它真正的等级。（这是引导词的意外反面：引导词**故意**重复一个 token，但**从不**重复意思。）
- **环境**也是一个事实来源——`package.json` 的 scripts、配置文件、目录布局、`--help` 输出——一份**重述**环境的文档是一个**缓存**：一次查找的副本，只有当那次查找很贵时才挣得负载。缓存那些 agent **查不到**的东西：没写下来的约定、某个选择背后的原因、任何配置都不肯承认的坑。把"一个文件、一条命令"就能查的东西留给环境，在那里它们不会过时。
- 每一行都检查**相关性（relevance）**：它还和这份文档要做的事有关吗？一行会因为**从不相关**（纯粹的铺陈，或一个本该披露出去的分支）或因为**行为/世界变化而过时**而失去相关性。**更短的文档更容易保持相关。** 没有修剪纪律，默认的命运是**沉积（sediment）**：过时的层因为"加进来感觉安全、删掉感觉有风险"而沉淀下来，直到你必须一层层往下打钻才能找到还活着的东西。
- 一句一句地猎捕**空操作（no-ops）**：一条模型默认就已经遵守的指令，是在付负载来说废话。检验标准——**它相对默认行为改变了什么吗？**——是**相对模型**的，不是相对读者的：两个人对某个 no-op 意见不一，其实是对**默认值**意见不一，靠**跑一遍文档**来定，而不是靠辩论。当一个句子没通过检验，**删掉整句**，而不是从里面抠词。这个检验也给引导词打分：一个弱到打不过默认值的词（当 agent 本来就挺彻底时还说 _be thorough_）是个 no-op，修法是换一个**更强的词**（_relentless_），不是换技术。
