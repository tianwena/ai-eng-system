# 深潜：数字真值登记机制（`facts.json` + `check-consistency.mjs`）

> 配套 `docs/技术文档-运行机制与技术亮点.md` 第 5.4 节。
> 一句话：让"关于体系自身的数字"做到——**说错了会红**。本文解剖它怎么做到、哪里做不到。
> 复跑：`node scripts\check-consistency.mjs`（含本文描述的全部规则）。

---

## 一、要解决的问题

**两类真实翻车**（不是假想风险）：

1. **数字分叉没人知道**：文档说 13 项、脚本里其实有 14 项；历史上这类腐烂发生过四次（检查项 13/14、44/80 项、技能数、脚本清单漏项）。
2. **措辞一改，声明从检查器视野里消失**：旧版每条声明只有"一个正则 + 一个命中计数"。实测把 README 的「技能总览（36 个）」改成「技能总览：共 36 个」、再改成 35，检查器**全绿**——因为同一个正则还在**同一文件的另一行**（安装脚本注释）命中，把"声明被改写"这件事遮住了。

> 教训：**命中数不是锚定**。真正的修法是把每条声明钉到"具体文件的某个行特征"。

## 二、目标与非目标

**目标**：关于体系自身的数字——"不许悄悄多一句，也不许悄悄少一句"（入口文档纪律 3 的机制化）。

**非目标**（同样重要）：

- 不保证文字质量——正常行文里的合法重复不会报红；
- **不做第二真相源**——登记表存的是"判据"，真值永远从文件系统/源码**现算**；
- **不给没有机器来源的数字背书**——一个没人自动维护的数字迟早会错；正确做法是把它从文档里删掉，改成不依赖精确计数的写法。

## 三、一条声明的解剖

`scripts/facts.json` 里一条 fact 的字段：

| 字段 | 作用 | 示例（`skill-total`） |
|---|---|---|
| `id` | 唯一标识，被外部清单钉住（见第八节） | `skill-total` |
| `说明` | 人读的用途描述 | 技能总数（写在哪几处） |
| `claim` | **带捕获组**的正则：从文档里抓"声明" | `(?:技能总览（\|合计\s*\|把\s*\|不要背\s*)(\d+)\s*个` |
| `truth` | 真值来源的名字，在 `truthSources` 里定义**怎么算** | `skills.total` → 数含 `SKILL.md` 的目录 |
| `noun` | 该声明使用的"数字 + 名词"组合（供未登记数字扫描） | `个技能` |
| `anchors` | 声明**具体落在哪个文件的哪一行**：`file` + `witness`（该行稳定子串，**去掉会变的数字本身**） | `README.md` + `## 二、技能总览（` |
| `noNumber` | 声明本身不带数字时（如"只锚定行、防这行被删"）跳过数字比对 | — |

## 四、四条硬规则（缺一条就 FAIL）

1. **锚点必须恰好命中一行**：0 行 = 声明被删或被改写；≥2 行 = witness 不够独特（钉不死）；
2. **那一行必须自己能被 claim 匹配**：否则说明声明被改写成了别的措辞；
3. **每个文件里 claim 的命中数 = 该文件登记的锚点数**；
   - 例外（防误报摩擦）：多出来的命中如果只是**复用已登记的数字**（例：另一处也写「技能总览（36 个）」，而 36 确实登记在册）→ 放行，只在摘要里计数提示；
   - 边界：这只保证"数字没有说谎"，**不保证"这句话不该重复"**——文字质量不在本表职责内；
4. **文件里出现的数字必须等于真值**——真值由 `truthSources` 现算；真值算不出来（来源不存在）同样 FAIL。

## 五、真值怎么现算（`truthSources`）

| 真值来源 | 算法 |
|---|---|
| `skills.total` / `skills.engineering` / `skills.productivity` | 数 `engineering/`、`productivity/` 下**含 `SKILL.md` 的目录** |
| `skills.selfAuthored` | `selfAuthoredSkills` 名单长度（并逐个核对目录存在） |
| `scripts.count` | 库根 `*.ps1`/`*.mjs` + `scripts/` 下全部文件（不含点文件） |
| `checks.qualityGateTotal` / `checks.qualityGateDefault` | `quality-gate.ps1` 里**不同 `Add-Result` id** 的个数（默认值再减去需 `-IncludeTests` 的那一项） |
| `checks.redline` | `redline-check.ps1` 里 `Sect` 出的检查项数 |
| `checks.selfTest` | `self-test.mjs` 的 `CASES` 条数 |
| `checks.verifyAll` | `verify-all.mjs` 的 `steps` 条数 |

核心原则一句话：**文档里的数字是"被检查的声明"，唯一的真相来源是文件系统。**

## 六、未登记数字的拦截

- **`registeredNumbers`**：按"数字 + 名词"登记允许出现的组合；任何**没登记**的组合被拦下。
  - 中文数字与全角数字会**规范化后按同一张表核对**（"九十九 = 99、１５ = 15"）——旧版对它们零防护；
  - 小数字例外：`smallNumberThreshold`（默认 10）以下的数字当**叙述性数字**放行（"先装 2 个技能试试"），避免"写一句散文就要改登记表"的误报摩擦。
- **`extraValues`**：不是由任何 fact 真值派生的数值必须写在这里并写明理由——**没有第三条路**（以前这里是一份手抄的真值副本，删掉一个数字没人发现）。
- **如实登记的盲区**：扫描只认**登记过的名词**。写一个未登记名词（例如"九十九个门禁"）它看不见——因为放宽成"任意量词 + 任意名词"会把本库 800+ 处中文自然语言打成误报（"一个人""三条铁律"这类）。所以新增一类体系数字时，**名词本身也要登记**，否则那道护栏不成立。这是明确取舍，不是遗漏。

## 七、走查：给体系加一个新数字要做什么

1. 想清楚**真值怎么现算**（算不出来 → 要么加进 `truthSources`，要么别写这个数字）；
2. 在 `facts.json` 加一条：`claim`（带捕获组）+ `truth` + `noun` + `anchors`（file + 该行稳定子串）；
3. 在 `registeredNumbers` 登记"数字 + 名词"组合（两位数以上的数字必须登记）；
4. 跑 `node scripts\check-consistency.mjs`；
5. **故意把数字改错一次**，确认它真的会红——"没验过会红"的护栏等于没有护栏；
6. 若目标文件里存在"会被测试用例输入原样命中"的行，用 `excludeLines` 排除那些行（登记表里已有一条 fact 记录了该字段的用途）。

**一个真实的演化案例**（`hook-selftest-count`）：提交钩子原本**写死**自检条数，结果一小时内漂了两次（34 → 36 → 37 → 38）——每次提交都打印一个错数字，等于工具在说谎。处置不是"再小心一点"，而是改成**运行时现算**（`grep -c` 数用例名）；随后这条 fact 的核对对象升级为"**现算方式本身**"（claim 锚定那行 grep，改坏了会红）。"写死的数字"被机制上消除。

## 八、它自己也被看着

- **`facts-integrity`**：每条 fact 必须至少有一个锚点（没有锚点的声明等于没人管）；真值来源必须真实存在；
- **`PINNED_FACT_IDS`**（钉在 `verify-gate-integrity.mjs`）：fact 的 id 清单**钉在登记表之外**——删掉一条 fact，会有人红；
- "登记了却没人扫"的假安心也被处理过：名词「个检查器」曾被登记但没有任何声明在使用，等于虚构了一层保护；现在它由 `verify-all-count` 这条真实声明持有（真值 = `verify-all.mjs` 的步骤数）。

## 九、失败模式对照表

| 你做的事 | 会红在哪 |
|---|---|
| 改错文档里的数字 | `registered-claims`：该锚点行的数字 ≠ 真值 |
| 改掉声明的措辞（锚点行不再能被 claim 匹配） | 锚点规则 ② |
| 删掉声明所在的行 | 锚点规则 ①（解析到 0 行） |
| 写一个没人用过的"数字 + 已登记名词"组合 | `unregistered-facts` |
| 写"数字 + 未登记名词" | **看不见**（已知盲区；需先登记名词） |
| 新增/删除脚本、技能、用例导致真值变化 | 引用该真值的所有锚点行一起核对：没同步改文档就红 |
| 把真值来源文件改名或删除 | `facts-integrity`（真值算不出来） |
| 删掉一条 fact | `PINNED_FACT_IDS` 外部比对 |

> 记录类文档（`docs/reviews/`）**不参与**这套扫描——它们是留档，不是声明；同一数字有两份出处就是本机制要防的"第二真相源"。

## 十、取舍与局限（一节说清）

1. **覆盖是白名单式的**：新名词不登记就看不见——为压制中文散文误报付出的明确代价；
2. **只保证数字、不保证句子**："数字没说谎"与"这句话该不该这么写"是两件事；
3. **锚点的脆弱性**：witness 是手工挑的稳定子串，大改版式时可能需要同步更新锚点——这是**有意的"显式动作"**（改版式的人必须当场面对这条声明），不是缺陷；
4. **它不产生知识**：真值来源本身算错了，这套机制发现不了——那要靠独立复审（"判据选对了吗"永远在人这一侧）。
