# 这里放的是什么（复审与验证留痕）

本目录是**证据**，不是宣传材料：每一次"改了 `scripts/`/`tests/` 之后必须起独立上下文 reviewer"的
结论、以及每一次在真实项目上的验证，都按 `<日期>-<基点 sha>.md` 存在这里。
**判据先写死、结果不许再改**；事后补齐的内容一律标"事后补记"。

## 公开版的内容范围与代号约定

本仓库公开发布时，对**被测项目的身份**做了匿名化处理，其余一字未改：

| 代号 | 是什么 | 未公开的部分 |
|---|---|---|
| `项目 A` | 一个 AI 对局平台 | 确切目录名、脚本文件名与行号、素材与业务细节 |
| `项目 B` | 一个量化 / 数据管线项目 | 库表名、类名、数据文件名 |
| `项目 C` | 一个桌面游戏 | 具体文件名、素材规模 |
| `项目 D` | 一个前后端 Web 小工具 | 数据文件名、接口数量 |

**判据、判定口径、结论、以及"体系自己哪里没做到"的记录，全部保留原样**——
被去掉的只是"它是谁"，不是"它出了什么问题"。原始记录（含真实名称与 `文件:行`）保留在作者的
本地开发仓库中。

## 一个必须说明的细节：文中引用的 commit SHA

各文件里引用的 `279bf64` / `c921ef9` 这类 SHA，属于**作者本地的开发历史**。
公开仓库是从匿名化后的工作树**重新起历史**的（见下），因此：

- 这些 SHA **在公开仓库里不存在**，`git show <sha>` 会失败；
- 文件名里的 `<基点 sha>` 也只对本地开发库有意义 —— 公开版请把它读成"某一轮的收口点"。

> **为什么不在公开仓库里保留原来那 73 个提交**：那些提交里含被测项目的真实名称与本机路径，
> 一旦推上去就**收不回**。重写本地历史又会把本地开发库的所有 SHA 换掉（本目录的文件名正依赖它们）。
> 所以选了第三条路：**本地开发库保持原样，公开仓库用匿名化后的树重新开始。**

## 读这些文件时的两个提醒

1. **"没跑成"是结论，不是失败**：本库的核心纪律是「没跑成 ≠ 通过」，所以你会看到大量
   "这一项没跑成/无法判定/已写明取舍"——那正是它想让你看到的东西。
2. **里面有作者自己犯的错**（恒真断言、把猜的当实测、没验证前提就改代码……），
   它们是故意留的：一个只展示"我全对"的验证工具，不值得相信。
