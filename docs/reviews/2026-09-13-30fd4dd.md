## 一、N1 是什么

**一句话**：`redline-check.ps1` 在项目不是 git 仓库时，「① 硬编码密钥」这一项**整项没有执行**，
顶层结论却打 `VERDICT: PASS（带警告）—— 无硬失败项` —— 读起来像"机器查了一遍、没发现硬伤"。

复现（判据写死之后、派活之前的一次探针，`docs/reviews/2026-09-13-three-projects-protocol.md` 有原记录）：

```text
① 硬编码密钥
  ✓ 未发现硬编码密钥 / 敏感文件泄露      ← 一个文件都没打开
...
VERDICT: PASS（带警告）—— 无硬失败项；警告请人过一眼
```

这与本库的核心教条「**没跑成 ≠ 通过**」正面冲突：差的是「**查过没有**」与「**没查**」。
值得注意的是——**三个子 agent 都如实报告了自己没查**，不达标的**在工具，不在 agent**。

## 五、遗留与取舍（**都已知、都可见，未做**）

1. **被跟踪且 >2MB 的文件不扫**（`continue` 跳过）。范围注 + 警告都报了它"没扫"，
   所以是**可见的取舍**不是静默漏报；范围注只给总数并注明"其中 N 个是被跟踪的"，
   没有拆成两条。第五轮复审把它列为建议项。
2. **`.gitignore` 覆盖检查只验证"规则行存在"**，不验证"该文件确实没被跟踪"。
   影响被"被跟踪的敏感文件"那条硬失败兜住了。
3. **③④ 的确认依据无内容校验**：`-Note "x"` 也是合法确认。现在输出会**朗读依据原文**，
   让人一眼看出这个确认值多少，但机器不判。
4. **退出码保持 0/1**（用户裁定）。全库其它检查器有第三档 `exit 3`（"没跑成"），
   红线没有；改它属于流程决定，未做。
5. **`-Quiet` + FAIL 只给条数**（`VERDICT: FAIL（N 处）`），不打印明细。
6. **git 夹具类用例在"无 git / 大小写敏感文件系统"上会走"跳过"分支** —— 等于在别的机器上
   退化为无护栏。本库其它检查器用例同样如此。
7. **第六轮复审没跑成**（断网）。`30fd4dd` 只有自检 + 变异测试。

## 六、怎么自己复跑这些结论

```powershell
# 全量（6 步：技能体检 / 一致性 / 闸门完整性 / 速查卡 / 自检 55 条）
node scripts\verify-all.mjs

# 只跑检查器自检（约 55 秒）

# 红线本身（在任意项目上）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\redline-check.ps1 -Project .
```

环境注意（都在这条线上真踩过）：

- `scripts/*.ps1` 是 **UTF-8 带 BOM**；`Get-Content -Raw` 读它们**必须** `-Encoding UTF8`，
  否则 PowerShell 5.1 按 GBK 解码 → 满屏乱码，容易被误判成文件损坏。
- **控制台代码页**：纯 936 控制台下，用例对中文输出的断言会假红（实测 10 条）。
  自检现在会**自动归一 + 还原**；手跑产品不受影响（产品在 936 下是对的）。
- 变异验证的做法：把库复制到 `%TEMP%`，**只改一处**实现，跑**完整**用例集，
  断言"只有对应用例红"；还原后再跑一次确认全绿。**不要按名字过滤子集**——
  第二轮复审就在这里踩过坑（过滤漏掉一条，得出"删掉实现也全绿"的假结论）。
