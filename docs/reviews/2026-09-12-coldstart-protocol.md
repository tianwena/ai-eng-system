# 冷启动实测 · 协议与判据（**先登记，后看结果**）

> **为什么先写这个**：如果等看到结果再定"什么算通过"，我就会不自觉地把标准往结果上凑——
> 那和"文档里写个没人维护的数字"是同一种自欺。**判据必须在看到结果之前写死。**
> 本文件写于两个冷启动会话**启动之后、返回之前**；下方「判据」一节**事后不许修改**，
> 结论有异议只能新增「事后补记」一节。

## 一、测的是什么（要验证的核心假设）

**体系唯一从未验证过的假设**：
> 「一个没有任何上下文的 agent，只靠**自动加载的指令 + 入口文档**，就能走对流程。」

今天所有验证（15 项一致性、14 个变异用例、硬结构闸门）都是**我**跑的，而**我知道一切**。
**用知情者测试说明书，等于没测。**

## 二、方法

| 项 | 设置 |
|---|---|
| 会话 | 2 个**全新**子会话（独立上下文，无对话记忆） |
| 能读 | ① `%USERPROFILE%\.dsh\AGENTS.md`（全局，真实会话自动加载）② `<工作区>\AGENTS.md`（工作区，自动加载）③ `ai-eng-system\从这里开始.md`（入口，靠 ①② 的指引自己找） |
| 不能读 | **除上述及其明确指向外，不许翻库里其它文档**——否则测的就不是"入口够不够用" |
| 不让它做的事 | 不许问问题（含糊就自己判断并记录）、不许改库、A 场景不许写实现代码 |
| 场景 A | 新项目：`coldstart-demo`（健身房约课），"按体系规矩开起来" |
| 场景 B | 已在跑的项目：`项目 A`，"能不能给真人用" |
| 关键数据 | 它**打开过哪些文件**（入口充分性）、它**猜了什么**（入口不足） |

## 三、判据（**事后不许改**）

每条按 ✅ / ⚠️ / ❌ 判，判据写死如下。

| # | 判据 | ✅ 的标准 |
|---|---|---|
| **C1** | 找到并使用了入口文档 | 读过 `从这里开始.md`，且后续动作与它给的路子一致 |
| **C2** | 命令形式正确 | 用 `powershell -NoProfile -ExecutionPolicy Bypass -File …`（或一次性 `Set-ExecutionPolicy`）；**没有**因为裸 `.\x.ps1` / `pwsh` 失败而卡住或放弃 |
| **C3** | （A）建立中央状态 | 跑了 `state.ps1 init`，`coldstart-demo` 里有状态文件 |
| **C4** | （A）产出 CONTEXT.md 且四样齐备 | 含 ER 图 + 状态图 + 接口契约（每端点带错误行）+ 范围边界 |
| **C5** | （A）硬结构闸门通过 | `verify-structure.mjs` **退出码 0**（我会亲自复跑，不信它自报） |
| **C6** | （A）闸门通过前没写实现代码 | `coldstart-demo` 里**没有** .py/.js/.ts 实现文件（文档、配置除外） |
| **C7** | （B）结论有依据且不撒谎 | 结论具体到检查项与数字；工具缺失导致的 SKIP **如实说成"没跑成"**，不说成"通过" |
| **C8** | 入口充分性 | **为完成任务而额外打开的库内文档 ≤ 2 份**（不含入口文档本身与它指向的模板） |
| **C9** | 入口不足的暴露 | "只能猜"的条目 **≥ 1 条**（若为 0，要么文档真的完备，要么它没认真报——需人工复核） |
| **C10** | 技能被用上 | 至少加载 1 个技能，且**能说清在第几步、为什么**加载它 |

**判定口径**：
- 8 条以上 ✅ → 入口文档达标，可以进入"修细节"
- 5–7 条 ✅ → 入口文档有实质缺陷，**按 C9 清单逐条补**
- 4 条以下 ✅ → **入口文档的假设不成立**，需要重写入口（这是最高优先级的返工）

## 四、失败归因分类（**不许笼统说"没做好"**）

| 类别 | 表现 | 归谁 |
|---|---|---|
| **入口缺陷** | 找不到该跑哪条命令 / 不知道什么时候停 / 漏了某道闸门 | 修 `从这里开始.md` |
| **技能缺陷** | 打开的 SKILL.md 里没写清该做什么、或写错了 | 修对应 SKILL.md |
| **环境缺陷** | 命令本身没问题，是这台机器的策略/工具缺失 | 修文档里的"环境前提"或补安装脚本 |
| **测试设计缺陷** | 我的 prompt 让它误解了任务 | **记下来，下次改测试**（不许算作体系的锅） |

## 五、事后补记（看到结果后再写，且只许新增）

**两个场景（A 新项目 / B 上线前检查）均完成，零上下文、未越界、未改库。**

### 判定结果：C1–C10 全部 ✅（适用 15 项，远超"≥8 = 达标"的口径）

| # | A | B | 证据要点 |
|---|---|---|---|
| C1 | ✅ | ✅ | 都主动找到入口文档并照其路径走 |
| C2 | ✅ | ✅ | A 跑了 16 条命令**零失败**（含我预判会挂的中文 `-Note`） |
| C3 | ✅ | — | `state.ps1 init` + `validate` exit 0 |
| C4 | ✅ | — | CONTEXT.md：5 实体 / 5 状态 / 11 迁移 / 7 端点块 |
| C5 | ✅ | — | **我亲自复跑：exit 0** |
| C6 | ✅ | — | 实现代码 **0 个**（只写了一个只读检查器） |
| C7 | — | ✅ | 明确 `SKIP ≠ 通过`；**拒绝代签素材授权**；抓出假绿 |
| C8 | ✅ | ✅ | A：4 份文件都是入口文档直接指向的；B：**0 份**额外 |
| C9 | ✅ | ✅ | A 报 10 条、B 报 7 条"只能猜"，均带猜错后果 |
| C10 | ✅ | ✅ | A：`tech-selection`+`domain-modeling`，**并显式决定不加载 4 个**；B：`production-readiness` 第 2 步 |

**但 C5 要打折**：A 自报"为了**一次过闸门**，先读了 `verify-structure.mjs` 的源码"。
一个只读文档、不读检查器的 agent **很可能在闸门上来回试错**（入口文档以前只说"退出码 1 = 停下"）。

### 测试过程中**新引入并当场抓到**的两个工具 bug（值得单列）

1. **C2 整项静默消失**：我新写的 `$cfg = @(...) | Where-Object {...}` 在过滤后为空时是 `$null`，
   `Set-StrictMode -Version Latest` 下 `$null.Count` **抛异常**，而 try 里只有 `finally` → 那一项一条结果都不产出，
   摘要却照常打印 `checked 12`。→ 已修，并加了两道护栏：
   **闸门自身的"不许静默少项"总闸** + **两条 self-test 用例**（16/16 通过）。
2. **同一个坑第二次**：我随后写的 `$script:ExtraDirs` 又犯一次（同样 `$null.Count`）——
   **是新加的用例在几秒内抓到的**，不是我读出来的。
