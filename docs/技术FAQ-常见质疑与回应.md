# 技术 FAQ：常见质疑与回应

> 配套 `docs/技术文档-运行机制与技术亮点.md` 的问答集，面向技术审视。
> 每条只给三样东西：**结论、机制/证据、边界（哪里不成立）**。
> 数字类证据的真值来源见技术文档第九节；数字护栏的深层机制见 `docs/深潜-数字真值登记机制.md`。
> 本文所有说法都可按技术文档第九节的命令复跑。

---

## 一、定位与对比

### 1. 这和 CI + linter + SAST 有什么本质区别？

**结论**：不替代，是叠加层——它管的不是"检查什么"，而是"**结论怎么说、责任怎么分**"。

**机制**：加固闸门内部**直接调用** gitleaks / semgrep / ruff / pip-audit / npm audit / pytest；本体系补的是三样现有生态不直接提供的东西：① 在绿/红之外加第三种结论"**没跑成**"（退出码 3 贯穿全链）；② 写代码之前的意图闸门（三张图 + 接口契约）；③ 给 AI agent 的作业与留痕协议。

**边界**：它不做增量分析、不做代码质量评分，也不管"代码优不优雅"。

### 2. 为什么不直接用 SonarQube 之类的平台？

**结论**：正交——那些解决"存量代码的健康度"，本体系解决"流程纪律与证据"。

**机制**：刻意零服务端依赖（Node + PowerShell 本机跑），不需要运维一套平台；CI 的核心收益（干净环境验证）用 `verify-clean-clone.mjs` 在本机复现，**避免把含敏感细节的仓库送上云**。

**边界**：团队规模化之后，平台化工具提供的协作能力是它没有的。

### 3. 它是不是绑定某款 AI 工具？

**结论**：机制层有偏置，**流程层可移植**。

**机制**：技能是纯 Markdown（`SKILL.md`），换工具的代价集中在"如何注入技能、如何被模型发现"这一层，需要重做配置；协议、闸门、状态机不依赖具体模型。

**边界**：这是已登记的短板之一（技术文档第七节），不是待澄清项。

### 4. 它管代码质量吗？

**结论**：管及格线，不管优秀线。

**机制**：红线是四道及格检查；加固闸门把"能跑"变成"敢给人用"。入口文档明确写着"**别把闸门当优秀线**"。

**边界**："有没有人要、能不能收钱"是商业闸门（G1/G2）的事，跟代码质量无关。

## 二、可信度

### 5. 自己审自己，凭什么信？

**结论**：靠四根支柱，不靠自觉。

**机制**：
1. **判据先写死**——通过标准在看到结果之前登记，事后只许"补记"；
2. **独立复审**——改的人不能判，reviewer 只拿 diff + "声称解决了什么"独立作业；
3. **变异测试**——给闸门注入已知错误，抓不住就红（57 个用例）；
4. **判据钉在被评对象之外**——期望清单不在闸门源码里，防止"删检查时源码和判据一起变小"。

**边界**：文档自己写了——自检只能证明"判据仍然成立"，**证明不了"判据选对了"**；后者没有机器能验，只能靠独立复审。

### 6. 文档里的数字怎么保证不腐烂？

**结论**：不靠记性——真值现算、声明钉行、未登记数字拦截。

**机制**：`scripts/facts.json` 登记每条声明（正则 + 锚点行 + 真值来源），`check-consistency.mjs` 逐条核对；**改错一个数字、删掉一行锚点、或改掉一句关键措辞都会红**，且这是提交钩子的必过项。

**边界**：只认登记过的名词——"数字 + 新名词"它看不见（如实登记在案）。详见深潜文档。

### 7. "判据先写死"会不会只是姿态？

**结论**：有流程约束，且被现实考验过。

**机制**：判据文件登记在 `docs/reviews/`，命名带基点 sha；事后只许新增"补记"。考验的例子：一次复审因断网**没跑成**，处置不是省略不提，而是**如实记成"没跑成，不算通过"**。

**边界**：这靠纪律兜底，没有机器能强制人不事后改判据——但改没改，留档可查。

### 8. 变异测试能证明什么、不能证明什么？

**结论**：证明闸门"活着且不狼来了"，证明不了判据完备。

**机制**：每个用例注入一个已知错误，断言必须 FAIL；另有"什么都不改必须 PASS"（防狼来了）和"**变异必须真的改到文件**"指纹闸（防变异落空造成的假绿/假红）。

**边界**：用例想不出来的错误类型它测不到——这正是"判据选对与否"必须靠人的原因。

## 三、效果与样本

### 9. 照出的问题真的被修了吗？

**结论**：工具侧的缺陷线修了；**项目侧修不修取决于人**——目前最完整的闭环是"体系修自己"。

**机制**：N1 线（"没查被说成查过"）走过完整的发现 → 多轮修复 → 独立复审 → 留档；项目侧有一个被照出的问题**没有**被假签，而是如实记成阻塞项（block）等授权。

**边界**：这套体系的价值定位是"更早、更便宜地知道答案"，不是"自动把答案修好"。

### 10. 只有四个项目，样本够吗？

**结论**：不够，且已如实标注。

**机制**：四个真实项目 + 几轮自审；"年轻、未经长期大规模验证"写在自己的局限清单里。验证方法完全可复跑（技术文档第九节给了全部命令）。

**边界**：扩大样本没有捷径——只能拿新项目继续跑。

### 11. 误报怎么办？会不会"狼来了"？

**结论**：误报被当成一级缺陷处理，且有针对性的机制。

**机制**：危险模式的 `eval` 假阳性（命中 `RiskEval()` 这类标识符）被修成词边界匹配并留痕；测试夹具里的假密钥用**行内豁免**（`redline-allow`，必须写在命中行、豁免条数必报、`-Quiet` 也报）；"狼来了"被显式当作设计风险——豁免机制存在的理由就是它。

**边界**：启发式判据的误报摩擦不可能归零：放宽会误报、收紧会漏报，取舍写在机制注释里。

## 四、工程性

### 12. 维护成本多大？

**结论**：真实存在，且是自认的最大成本项。

**机制**：三个不对称设计在压成本：
1. 能机器核的绝不靠人——一致性 / 完整性 / 自检等共 6 个检查器收敛成一条命令；
2. **两档复审**——只有改检查器/闸门（改错会静默关掉一整类保护）才强制独立复审，改文档不强制；
3. **做减法**——G1–G4 默认关闭（"一个没人跑的闸门等于没有闸门"）。

**边界**：文档偏重是自认的短板；一条缺陷线走过数轮复审，就是这套成本的实测样本。

### 13. 平台锁定？（Windows）

**结论**：核心脚本为 Windows / PowerShell 5.1 实测；Linux 侧**未真机验证**。

**机制**：CI 模板同时给了 Windows 与 Linux 两条；.mjs 系列检查器跨平台。

**边界**：如实登记为局限，不做超出证据的宣称。

### 14. 性能开销？

**结论**：两级闸门对应两种场合：红线**秒级**（日常），加固闸门**分钟级**（上线前）。

**机制**：`verify-all` 含自检约一分钟；`--fast` 可跳过自检，但**退出码仍是 3**——跳过"证明其他闸门还活着"的一步，就不是完整结论。

**边界**：这份"慢"是刻意的：变异测试要复制仓库并起 PowerShell。

### 15. 数据安全？

**结论**：全程本机、零外泄设计。

**机制**：所有检查器本地运行；`verify-clean-clone.mjs` 用临时 clone + 干净环境复现 CI 收益，规避"上云 CI"的暴露面；含安全细节的记录文档按理由豁免于部分扫描（例如 `no-hardcoded-paths` 的豁免名单）。

**边界**：仓库本身要不要公开、推到哪，是使用者的决定，不在本体系控制内。

### 16. 各检查器退出码不完全一致——为什么？

**结论**：如实存在的差异，属用户裁定，已登记在局限清单。

**机制**：红线按裁定保持 `0/1`（兼容既有消费方），"没跑成"通过**结论行三档文案**表达（`PASS（有 N 项没跑成）`），`-Quiet` 下也照打，机器侧读 stdout；其余检查器用 `0/1/3`（`quality-gate` 在 strict 模式下另有 `2`）。

**边界**：这弱于其他检查器的机器可读语义，属于已知取舍。

## 五、流程与角色

### 17. 谁会真的用它？会不会变成自我满足的仪式？

**结论**：适合"AI 重度协作 + 结果有真实后果 + 愿意先对齐意图"的人；仪式的风险有专门设计在防。

**机制**：三条反仪式设计——① 红线轻量化到秒级（太重就没人跑）；② 两档复审（不把强制面铺到每处措辞，避免规则被形式化架空）；③ 留痕不强制，而"伪造没有成本、真做过才留"。另有一个现实判据：**如果连续几轮验证产出的全是"项目缺陷"，说明工具已经够好，该停止自转、去干活**。

**边界**：它不保证成功——有没有人要、能不能收钱，只有市场能回答。

### 18. 用户不在线怎么办？

**结论**：三档降级，写死在入口文档里。

**机制**：事实类问题自己查（查不到就标明）；决策类问题可带假设前进，但三条同时满足——假设落文件、改起来便宜、**不许越过闸门**；不可逆 / 花钱 / 对外的动作一律停下等人。判据一句话：**假设能写进"待确认"一节 ≠ 可以做**。
