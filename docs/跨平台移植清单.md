# 跨平台移植清单（Windows → Linux / macOS）

> **这份文件的用途**：把"这套体系的闸门能不能在 Mac/Linux 上跑"从**传闻**变成**可执行的清单**。
> 现状是：**核心脚本为 Windows PowerShell 5.1 实测；非 Windows 侧从未真机验证**。
>
> ⚠️ **纪律（本库自己的）**：**没跑成 ≠ 通过**。所以这份清单里的任何一项，
> 在**真机跑过之前都不算完成**；也**不许**在看清单之后就把 README 里的平台承诺改宽 ——
> 那正是"文档说了、机器没验"的老毛病。

## 二、移植项（按工作量，逐项带判据）

### T1（小）· 可执行文件探测：`powershell.exe` → 先 `pwsh` 再回退

- **改哪**：`scripts/*.mjs` 里凡是拼 `…\WindowsPowerShell\v1.0\powershell.exe` 的地方（`self-test.mjs` 6 处最典型），以及文档里给的调用示例。
- **怎么改**：抽一个 `findPs()`：`pwsh` 在 PATH ⇒ 用它；否则回退 `powershell.exe`；都找不到 ⇒ **该用例记"没跑成"**（不是失败）。
- **判据**：在 Linux 上跑 `node scripts/self-test.mjs`，**不再出现 ENOENT**；本机（Windows）上 57 条仍应全绿。
- **风险**：低。但注意 PS7 与 5.1 的差异（见 T2）。

### T2（中）· 参数化 PS 专有构造

| 子项 | 改法 | 判据 |
|---|---|---|
| 控制台代码页 / `[Console]::OutputEncoding` | 用 `$IsWindows` / `$PSVersionTable` 判断，非 Windows 直接跳过这一整段 | 逻辑上不进入该分支；且**那条"936 控制台"用例在非 Windows 上记"没跑成"**而不是红 |
| `cmd.exe /c` 的字节级重定向（拿 git 的原始字节） | 非 Windows 分支直接用 `& git …` + `[Console]::OutputEncoding = UTF8`（Linux 默认就是 UTF-8） | 中文名文件在 Linux 上同样能被扫到（对应现有用例） |
| 临时目录 | `[System.IO.Path]::GetTempFileName()` 本身跨平台 ✓，但拼路径别用 `\` 字面量 | 无硬编码 `\` |
| BOM 要求 | **只对 `.ps1` 强制**（PowerShell 5.1 需要）；`.mjs` 按 `.gitattributes` 是 LF 无 BOM ✓ | `verify-ps1.mjs` 的 BOM 判据不误伤 `.mjs` |

### T3（中）· 在 Linux 上真跑一遍 CI

- **改哪**：不用改代码，**先跑**。`scripts/quality-gate.workflow.yml` 已有 `ubuntu-latest` job。
- **判据**：该 job 真的绿，且**它不是靠"跳过一切"绿**的 —— 要能看到 E 段（pytest）、B 段（pip-audit）、C 段（semgrep）真的跑过；SKIP/NOTRUN 要有逐条原因。
- **为什么必须**：现在 README/报告都写着"Linux 未真机验证"，这句话只有在真跑过之后才能删。

### T4（大）· 状态机 `state.ps1` 的去留

`state.ps1`（状态机 + schema 校验）是被文档引用最多、也最难移植的一块。两条路：

| 方案 | 代价 | 收益 |
|---|---|---|
| (a) 保留 PowerShell，但要求 **PS7+** | 使用者必须装 pwsh（Linux/macOS 上可装） | 改动小；但要实测 PS7 下的行为（本机**没有 pwsh，无法判定**） |
| (b) 重写为 `.mjs` | 工作量大，且它有一整套自检用例与 schema 判据要跟着搬 | 双平台原生；与其它检查器统一 |

**判据（两条路都要）**：`state.ps1` 的现有自检用例（含坏样例、schema 关键字白名单）在新实现上**逐条仍然会红/会绿**——否则就是"移植掉了判据"。

### T5（小）· 文档与承诺

- `README.md` 的「运行环境」段（已加）在移植完成前**保持现状措辞**；
- 移植完成后要同步更新：`给外人看的验证报告.md`、`docs/给非技术用户的使用指南.md`、
  `技术FAQ-常见质疑与回应.md`、`技术文档-运行机制与技术亮点.md` 里那几处"Linux 未真机验证"。

## 三、不该做的事（反模式）

1. **别用"看起来能跑"代替"真跑过"**：PS7 与 5.1 在**隐藏项枚举**和 **BOM/编码**上行为不同 ——
   典型症状是"全绿，但少扫了一批文件"（本库为此专门写过检查器，见 `check-consistency.mjs` 的目录枚举那段注释）。
2. **别为了让 CI 绿而把检查降级成 SKIP**：那正是本库最反对的"没跑成被读成通过"。
   非 Windows 上跑不了的项目**就记"没跑成"并说明原因**。
3. **别在移植 PR 里顺手改判据**：移植的目标是"同样的判据在另一个平台成立"，
   判据要改就单独一个提交、并按纪律 6 走独立复审。
